# ADR-002：审计链哈希设计

- **状态**：已接受
- **日期**：2026-08-29（追溯建档）
- **涉及**：`src/utils/auditChain.js`、`AuditLog` 模型、`scripts/resign-audit-hmac.js`

## 背景

审计日志是安全事件的事后证据，需满足两点：**防篡改**（任何对历史记录或插入/删除的改动能被检出）与**可验证**（验证方无需信任写入方即可核对）。

## 决策

采用「单向哈希链 + HMAC 签名」双层结构，追加写（append‑only）：

- **链结构**：每条记录含 `prevHash`（上一条哈希）、`hash`（本条哈希）、`hmac`、`hashVersion`。链序以 `_id` 降序近似。
- **哈希算法**：SHA‑256，输入为 `prevHash + '|' + canonicalPayload`。`canonicalPayload` 经 `stableStringify` 递归按键排序，保证序列化稳定。
- **载荷版本化**：`hashVersion` 分三档——v1 仅 9 字段；v2 全量业务字段；v3 在算哈希前先补齐 schema 默认值。新增字段不破坏旧记录验证。
- **校验**：按 `hashVersion` 选口径，重算 `computeHash()` 与存量 `hash` 比对；v2 存量走 `canonicalPayloadV2LegacyBatch`，以区分「默认值漂移」与真实篡改，避免误报。
- **HMAC 层**：`HMAC‑SHA‑256(HMAC_SECRET, hash)`，输入仅为 `hash` 十六进制串。

## 理由

- **哈希链**解决「改动/删除/插入可检出」：改动任一记录会使后续所有 `prevHash` 对不上，形成断链。
- **HMAC 叠加**解决「攻击者拿到数据库写权限后可重算整条链」：无 `HMAC_SECRET` 则无法伪造合法 `hmac`。
- **载荷版本化**是关键工程取舍：Mongoose schema 演进（新增字段带默认值）若不版本化，会让全部历史记录验证失败，等于自毁校验能力。

## 备选方案

- **仅哈希链（无 HMAC）**：可检出意外损坏，但挡不住持有库写权限的主动篡改者重算链。
- **仅 HMAC（无链）**：每条独立签名，无法检出删除/插入中间记录。
- **Merkle 树**：查询/增量维护成本高，审计场景按序追加，线性链已足够。
- **区块链/外部公证**：引入外部依赖与成本，超出当前合规需求。

## 后果与局限

- **写串行化**：链尾「读→算→写」必须互斥，引入进程内锁，见 [ADR-004](./ADR-004-审计链单进程锁假设.md)。
- **HMAC 换钥**：因 `hmac` 仅覆盖 `hash`，换 `HMAC_SECRET` 后可用 `scripts/resign-audit-hmac.js` 对新钥批量重签，无需旧密钥。
- **非实时强一致**：链以 `_id` 降序近似，极端并发下以锁保证，见 ADR-004 的单进程前提。
