# ADR-003：密钥管理策略

- **状态**：已接受
- **日期**：2026-08-29（追溯建档）
- **涉及**：`src/config/secrets.js`、`src/config/validate.js`、`src/utils/encryption.js`、`scripts/migrate-mfa-secret.js`、`scripts/resign-audit-hmac.js`

## 背景

系统依赖多把密钥（JWT 签发、数据加密、审计签名、登录 ECDH 私钥等）。需要明确：密钥从哪来、如何注入、如何轮换、以及启动期如何拦截弱配置。

## 决策

**1. 密钥清单与用途**（`src/config/secrets.js:28`）：

| 密钥                                                                                                                | 用途                                 |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `JWT_SECRET` / `JWT_REFRESH_SECRET`                                                                                 | 访问 / 刷新令牌签发（HS256）         |
| `AES_SECRET_KEY`                                                                                                    | MFA TOTP seed 落库加密               |
| `HMAC_SECRET`                                                                                                       | 审计链 `hmac` 签名 + 通用 HMACSigner |
| `LOGIN_ECDH_PRIVATE_KEY`                                                                                            | 登录口令信封加密（见 ADR-001）       |
| `MONGODB_URI`、`MONGO_ROOT_PASSWORD`、`ADMIN_INITIAL_PASSWORD`、`DOCS_PASSWORD`、`LOG_SHIPPING_TOKEN`、`SENTRY_DSN` | 基础设施与集成                       |

**2. 文件注入（`*_FILE`）**：`hydrateSecretsFromFiles()`（`secrets.js:55`）读取 `<NAME>_FILE` 指向的文件，去尾换行后回填 `process.env[NAME]`，适配 Docker secrets。`NAME` 与 `NAME_FILE` 同时存在且不一致时告警并以文件为准；读取失败直接抛错，不静默跳过。

**3. 静态加密算法**：`src/utils/encryption.js` 用 AES‑256‑GCM 加密 MFA seed（唯一消费者 `utils/mfaSecret.js`），密文格式 `gcm:<ivHex>:<authTagHex>:<base64>`，落库带 `enc:v1:` 前缀。遗留 CBC 解密默认关闭，须显式 `ALLOW_LEGACY_CBC_DECRYPT=true` 才启用（防填充预言机）。

**4. 启动期强校验**：`src/config/validate.js` 在生产环境强制拦截弱密钥（黑名单 + 长度 <32）、`MONGODB_URI` 含 localhost、缺 `CORS_ORIGIN`、非法 `TRUST_PROXY_HOPS`，失败 `process.exit(1)`。

**5. 轮换脚本**：

- `npm run rotate:mfa-secret`：轮换 `AES_SECRET_KEY` 时，用旧钥解密 → 新钥重加密 `users.mfaSecret`，逐条回读校验。**不经此脚本直接换钥，会导致已加密的 MFA secret 无法解密、TOTP 校验静默失败。**
- `npm run rotate:audit-hmac`：轮换 `HMAC_SECRET` 后对存量审计记录重签（见 ADR-002）。

## 理由

- **文件注入**让密钥不落 `.env` 明文、不进镜像层，符合容器化部署的 secrets 最佳实践。
- **启动即校验**把「弱密钥上线」从运行期风险前移到部署期硬失败，避免静默降级。
- **加密格式带版本前缀**（`enc:v1:`）为未来换算法/再轮换留出迁移空间。

## 备选方案

- **仅 `.env` 明文**：最简单，但密钥入仓/入镜像风险高，已被文件注入取代。
- **外部 KMS（云厂商托管）**：安全性更高，但引入外部依赖与成本，当前单机/私有化部署场景收益不足，列为规模化后评估项。

## 后果与局限

- **`.env` 存量明文待轮换**：当前 `.env` 仍含真实 `JWT_SECRET`/`AES_SECRET_KEY`/`HMAC_SECRET`（优化清单 R-1，P0）。部署前须全量轮换并按上文脚本迁移 `mfaSecret`，再迁到 `secrets/` 文件注入。
- **JWT_SECRET 轮换代价高**：轮换会使全部存量令牌失效、用户被强制登出；当前无配套脚本，轮换需在维护窗口执行。
