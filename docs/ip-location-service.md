# IP 归属地服务（ipLocationService）说明

本文件承接 `src/services/ipLocationService.js` 文件头的论证（注释密度棘轮按文件封顶，论证移此，代码内只留一行指针；行内不变量注释仍在原处）。

## 它做什么

给后台界面把裸 IP 翻译成「国家·省·市·运营商」可读串：会话管理、安全审计核查时，运营商标级归属地比点分十进制更有辨识度（一眼看出「这台设备在深圳、走电信」，而不是对着一串数字回忆）。

## 为什么是本地离线检索而不是在线 API

归属地是纯增强信息，若为它引入一次外网往返，sessions 接口的耗时会从毫秒级抬到秒级且不可控（第三方限频、断网、SSRF 面都进来了）。改用仓库内置的 ip2region xdb 数据（见 `src/utils/ip2regionSearcher.js`），全内存二分检索约微秒级，列表页加载速度不受影响；进程内再做一层结果缓存，同一 IP（同会话反复刷新）直接命中。

## 懒加载独立层（F4，2026-11-03）：句柄三态

`undefined`（未加载）| `false`（加载失败哨兵）| 检索句柄。两层失败语义严格分开，不能共用一个布尔：

- **加载失败**（数据文件缺失/损坏，loadDataFile 抛错）：置 false 哨兵 + 一次性告警闩 + 后续查询短路返回 null。没有哨兵的话，每条查询都要重做一次 11MB 的同步读（fs.readFileSync）——故障被放大成每请求数十毫秒的事件循环阻塞。哨兵 5 分钟过期重试一次：数据文件被修复后无需重启进程即恢复；告警闩在成功后复位，每个故障回合只告警一次。
- **运行期异常**（句柄已加载成功后 searchRaw/formatRegion 抛错）：**不置位**加载闩，逐条 warn（60s 节流）返回 null。它与「数据不可用」是两回事：句柄还好好的，逐条降级即可；把运行期异常当成加载失败会让一次畸形输入杀掉整个归属地面 5 分钟。

## 失败语义（fail-soft）

归属地查不出 ≠ 会话有问题。任何异常一律返回 null，调用方省略展示即可，绝不影响会话列表本身；失败结果不入缓存——数据恢复后下一条查询立即用上新结果，不拿旧 null 长驻。
