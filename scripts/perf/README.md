# 压测资产与基线记录（E-1）

> 目的：把「性能没问题」从感觉变成留档数字。本目录提供可复现的压测脚本、
> explain 抽查工具，以及基线记录模板。**基线没有实测值就不是基线**——
> 首轮跑完把真实数字回填到「基线留档」表，后续每次变更对照回归。

## 资产清单

| 文件                   | 用途                                                           |
| ---------------------- | -------------------------------------------------------------- |
| `k6-core-journeys.js`  | k6 核心旅程压测（登录 + 列表读 + 深分页对照），含 P95/P99 阈值 |
| `explain-spotcheck.js` | mongoose explain 抽查：高量级列表是否走索引（COLLSCAN 检测）   |

## 环境要求

1. **压测专用库**：`MONGODB_URI` 指向独立实例；造数 ≥10k 条告警/巡检/设备
   （小数据量测不出深分页与索引差异，结论无效）。
2. **开关**：`LOGIN_CAPTCHA_ENABLED=false`；`LOGIN_ENCRYPT_STRICT` 保持默认不开。
   压测结论代表「认证之后」的链路容量；加密/验证码开销不在此口径内。
3. **凭据**：`K6_USER` / `K6_PASS` 经环境变量传入，不写进任何文件。
4. **限流豁免或调高**：压测流量会命中限流器，需对压测来源调高配额或加入白名单，
   否则测到的是限流器而不是系统。

## 运行

```bash
# k6（安装：见 https://grafana.com/k6 ；winget install k6 或发行版包管理）
k6 run -e BASE_URL=http://127.0.0.1:3000 -e K6_USER=<账号> -e K6_PASS=<口令> \
  scripts/perf/k6-core-journeys.js

# explain 抽查（对目标库只读）
node scripts/perf/explain-spotcheck.js
```

## 游标深潜（正式基线用）

脚本内的「深分页对照」首轮只有 offset 深页是真实深页；游标侧请按此串联：

1. 首页请求 `GET /api/alarms?limit=20`，取响应 `nextCursor`；
2. 用 `?cursor=<nextCursor>&limit=20` 逐页推进 N 次（N 建议 ≥100）；
3. 记录第 N 页耗时，与同深度 `?page=N` 的 offset 耗时对比。

## 变更回归规则

- 任何涉及列表查询/索引/中间件链路的改动，合并前跑一次本压测，
  P95 不得劣于基线 10%（超出需解释或修复）。
- 新增集合级索引后，重跑 `explain-spotcheck.js` 并更新结论行。
