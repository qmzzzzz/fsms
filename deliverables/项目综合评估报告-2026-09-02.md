### 4.3 已验证的防护（回归测试应守住的设计）

**认证链路（`middleware/auth.js`）—— 超常规加固，切勿回退**

- JWT 锁定 `algorithms: ['HS256']`，阻断 `alg:none` 与算法混淆
- `tokenVersion` **强制存在且匹配**：伪造令牌省略该字段绕不过会话吊销
- `passwordChangedAt` 与 `iat` 秒级比较（规避同秒误拒）
- 角色一律取实时 `freshUser`，**不信任 token payload 中的角色快照**——撤销角色后旧 token 立即失效
- 设备级 `sid` 会话校验、用户 IP 允许范围校验、令牌黑名单
- 黑名单/会话服务故障一律 **fail-closed 转 503**，不静默放行

**数据范围（`middleware/rbac.js`）**

- `applyDataScopeToQuery` 对 `department` 为空等边界情形**显式返回 false**（deny 语义），而非回退到"零过滤放行全部"——历史上这里曾是越权入口，已修复
- `isRecordInScope` 支持数组路径取值（如 `maintenanceRecord.operator`），避免中间层为数组时校验恒失败

**注入防护（`middleware/security.js:166-206`）**

- `sanitizeMongo` 递归清洗 `body/query/params`；删除 `$` 前缀键、含 `.` 的键
- **深度上限 10** 防栈溢出；同时剔除 `__proto__`/`constructor`/`prototype`（原型污染）
- `hpp` 防参数污染；`queryScalarGuard` 防 `?search[$regex]=` 解析为对象
- 全仓扫描确认：无 `$where`、无 JS `eval`、无 `new Function`、无用户输入直传 `new RegExp`

**密钥与部署**

- 四把核心密钥均 **64 字符强随机值**，`config/validate.js` 启动期强制校验弱密钥
- `.env` 未被 git 跟踪；`Dockerfile` 用显式 `COPY src/` 而非 `COPY . .`（规避 `.env` 入镜像）
- 部署配置（`docker-compose.yml`/`deployment/`）无硬编码密钥；MONGODB_URI 无内联凭据
- 对称加密用 **AES-256-GCM** 认证加密（防密文篡改与填充预言机）

**前端**

- 全仓**零** `v-html`、零 `innerHTML`/`outerHTML`/`document.write`
- 令牌走 httpOnly + `SameSite=strict` + 生产 `secure` Cookie；Web Storage 仅存非敏感界面状态
- 路由守卫以 `/auth/me` 后端探测为准，非纯本地判断

**日志**

- morgan 自定义 `safe-url` token 调用 `redactUrlQuery`，避免 URL 中令牌明文长期落盘（很多项目会漏这一处）

### 4.4 审计限制

本次为**纯静态审查**，未做动态渗透测试、未做模糊测试、未逐条验证业务逻辑越权组合路径。建议生产发布前补充一次动态测试。

### 5.2 日志规范（优 9/10）

- **级别准确**：配置降级用 warn、可恢复重试用 warn、重试耗尽 error + `process.exit(1)`；80 处业务日志中越权尝试/敏感操作统一 `logger.warn` 带结构化上下文。
- **TraceID 贯穿**：`requestId.js` 每请求生成 16 位十六进制 ID，外部传入值经 `/^[a-zA-Z0-9-_]{1,64}$/` 白名单校验防日志注入；`logger.js` 用 AsyncLocalStorage **业务代码零改动**自动注入。
- **可检索**：生产 JSON 格式，双 transport 按天轮转（combined 全量 + error 仅错误级），崩溃堆栈独立落 `exceptions-*.log`。
- **留存一致**：日志 `maxFiles` 与审计库 TTL 共用 `constants/retention.js` 的 `RETENTION_DAYS`，修复了"审计记录还在、原始日志已被删"的取证断档。
- **脱敏**：密钥注入日志"只记变量名不记值"；81 处日志调用未发现 password/token/secret 原文。

### 5.3 监控指标（优 9/10）

- 零依赖自实现 Prometheus 文本格式（243 行，不引入 prom-client）
- 暴露 `http_requests_total`、`http_request_duration_seconds`（11 桶直方图，支撑 P50/P95/P99）、`security_alerts_total`
- **高基数防护**：route 标签取路由模板（`/api/devices/:id`）而非原始 URL——这是自实现指标方案的常见缺陷，本项目已规避
- 采集异常 try/catch 隔离，"指标采集失败绝不影响业务响应"
- 双消费通道：运维 Prometheus + 管理面板 `GET /api/metrics`（需 `security:audit` 权限）

### 5.4 错误处理（优 9/10）

- DB 连接指数退避重试（3s→30s 封顶）；优雅关闭多步骤清理，单步失败不中断后续
- `exitOnError: false` 保护"退出前 flush 审计缓冲"不被 winston 默认 `process.exit(1)` 抢先破坏
- 用户侧固定文案不泄漏内部细节，开发者侧结构化上下文 + 机器可读错误码（`LOGOUT_REVOKE_FAILED` 等）

### 9.3 环境限制

1. **本项目不是 Git 仓库**（无 `.git` 目录）——"文件是否入库"无法用 `git ls-files` 验证，只能人工核对 `.gitignore` 文本。
2. **`npm audit` 在部分环境中不可执行**：`registry.npmjs.org` 的 `/-/npm/v1/security/audits/quick` 返回 400（网络策略拦截），`registry.npmmirror.com` 返回 `NOT_IMPLEMENTED`，`api.osv.dev` 超时。依赖 CVE 结论以 2026-09-01 官方 registry 实测（0 vulnerabilities）为准，建议每次发版前在可联网环境复跑。
3. `npm outdated` 对本仓库（后端 692 包）会超过 120s 超时，判断陈旧度需挑关键包逐个 `npm view <pkg> version`。
4. Git Bash 的 `/tmp` 与 Node 解析不一致（shell 写 `/tmp/x.json`，Node 会找 `<盘符>:\tmp\x.json`），临时文件须写项目目录内相对路径。
